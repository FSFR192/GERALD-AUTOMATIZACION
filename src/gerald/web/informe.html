1. Términos LCEL Identificados en el Código

El LangChain Expression Language (LCEL) constituye la base sintáctica para componer Runnables, vincular configuraciones de metadatos, serializar y transformar salidas con tipado estricto mediante Pydantic:

Término LCEL Ubicación en Archivos Líneas Descripción y Propósito en el Proyecto
ChatModel src/gerald/llm.py 12-26 Instancia de ChatGoogleGenerativeAI o ChatOllama que actúa como el Runnable ejecutable central.
.with_config() src/gerald/llm.py 23, 26 Inyecta etiquetas semánticas (ej. tags=["rol:vision"], tags=["rol:evaluador"]) para trazabilidad en LangSmith.
.with_structured_output() src/gerald/agents/a2_boceto.py 71, 98 Encadena el modelo al esquema Pydantic InterpretacionBoceto y TextosBoceto (OCR) garantizando salida validada.
.with_structured_output() src/gerald/decision/decide.py 54 Encadena el evaluador LLM al contrato Decision (evalúa coherencia, puntaje y confianza numérica).
.invoke() src/gerald/llm.py 32 Método de ejecución sincrónica del LCEL: modelo.invoke(mensajes) integrado con traducción de fallos a P05.
SystemMessage src/gerald/agents/a2_boceto.py 74, 105 Mensaje de rol de sistema para fijar el contexto estricto del agente de diseño sin admitir inyecciones.

run_name / metadata src/gerald/observabilidad.py 22-23 Diccionario de configuración de runtime pasado al invocador del grafo para identificar cada pedido en LangSmith.

Código Fuente Representativo: Cadena LCEL del Agente A2 Boceto

# src/gerald/agents/a2_boceto.py (Líneas 65-80)
class InterpreteVision:
    """Implementación de producción del puerto InterpreteBoceto con Gemini Visión."""
    def __init__(self) -> None:
        from gerald.llm import get_llm
        # LCEL: Modelo de lenguaje + OutputParser estructurado Pydantic
        self._llm = get_llm("vision").with_structured_output(InterpretacionBoceto)

    def __call__(self, pedido: PedidoEntrada) -> InterpretacionBoceto:
        from langchain_core.messages import SystemMessage
        from gerald.llm import invocar_con_errores

        # Invocación LCEL con mensajes multimodales (Sistema + Imagen Base64)
        borrador = invocar_con_errores(
            self._llm,
            [SystemMessage(SISTEMA), _mensaje_boceto(pedido)],
            AGENTE
        )
        return borrador.model_copy(update={"agente": AGENTE})

2.2 Puntos Human-In-The-Loop (HITL)

HITL 1: Admin

Nodo: revision_admin

Se activa ante pedidos con confianza media/baja o costos mayores a S/ 300.00. Pausa con interrupt() y reanuda en POST /revision/{id} con SLA de 24h.

HITL 2: Cliente

Nodo: aceptacion_cliente

El cliente recibe la cotización formal y acepta con 1 clic en el portal. Reanuda mediante POST /pedidos/{id}/aceptacion.

HITL 3: Almacén

Nodo: espera_abastecimiento

Se detiene cuando hay quiebre de stock de insumos. Se reanuda en cuanto almacén registra la entrada en POST /almacen/ingresos.

5. Las Cuatro Capas del Ecosistema LangChain

1. LangChain Core

langchain-core >= 0.3

Primitivas base: clase Runnable, decorador @tool, tipado de mensajes (SystemMessage, HumanMessage) y serialización de checkpoints con JsonPlusSerializer.

2. Integraciones LangChain

langchain-google-genai, langchain-ollama

Conexión a modelos fundacionales: ChatGoogleGenerativeAI (Gemini 3.8 Flash con visión), ChatOllama (Llava local) y salida tipada con .with_structured_output().

3. LangGraph

langgraph >= 1.0, checkpoint-postgres

Orquestación con estado cíclico mediante StateGraph(GeraldState), persistencia en PostgreSQL / memoria, políticas de reintento (RetryPolicy) e interrupciones HITL (interrupt()).

4. LangSmith

langsmith >= 0.2

Plataforma de observabilidad y gobernanza de producción: registro de latencias, auditoría de pasos, visualización en cascada (Trace Tree) y anonimización de datos sensibles.

Iteración 1: Automatización del Núcleo Organizacional (Single Business)

Constitución (Definida por el Humano)
  • Determinismo Matemático: Ningún LLM alucina metros ni precios; recetas ejecutadas en Decimal.
  • Tolerancia Cero a Sobregiro: Si falta stock, el pedido se detiene y notifica a almacén.
  • HITL Obligatorio: Interrupción transaccional si la confianza no es alta o costo > S/ 1,500.
  • Idempotencia: Cero pedidos duplicados mediante hash SHA-256 de contenido y archivo.
Mapeo de Procesos (BPMN As-Is vs To-Be)
  • AS-IS Tradicional: 3 a 5 días hábiles, intercambio manual de correos, mermas por cálculos en Excel.
  • TO-BE Multiagente: 1.5 segundos en emitir cotización vinculante con reserva de insumos.
  • Carril Almacén: Interviene solo ante quiebres de existencias y reanuda el grafo.
  • Carril Administrador: Torre de Control HITL por excepción.

Iteración 2: Identificación del Deep Agent & Escalado Multi-Tenant

El Deep Agent en LangGraph

El Deep Agent coordina el ciclo completo de vida del lote a través de una máquina de estados cíclica con memoria compartida (GeraldState). Integra percepción visual (Gemini Vision), cálculo exacto de inventario, auto-reflexión política y capacidad de congelar su hilo de ejecución (interrupt()) ante decisiones humanas (HITL).

Arquitectura Multi-Tenant Corporativa

Evolución a Gerald Enterprise OS: soporte nativo para Entel Perú S.A. (C-ENTEL-PE), Banco BCP (C-BANCO-BCP), Interbank (C-INTERBANK) y Claro Perú (C-CLARO-PE). Aislamiento criptográfico mediante claims de tenant en el token JWT y particionamiento de consultas.
